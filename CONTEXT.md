# Morrow context

Morrow is a personal workspace platform run as a single instance (the owner's Dokploy box) with open sign-up. Sync is described in `docs/adr/0001-electric-tanstack-db-sync.md` and `docs/adr/0002-sync-invitations-and-workspaces.md`.

## Glossary

- **Workspace** — the unit users create, share and are members of. Has a slug, members, roles and activity.
- **Member** — a user's membership in a workspace, with a role (static owner; viewer, member, admin editable per workspace). Every role can read its workspace; being a member means being able to see it.
- **Invitation** — a pending offer to join a workspace. Only pending ones are synced; an accepted or cancelled one leaves the browser.
- **Project** — a named container of work inside a Workspace, with a key, an icon, an optional background and its own Columns. Every Member sees every Project. Can be archived; an archived Project is read-only until restored or deleted.
- **Project key** — 2–6 upper-case letters and digits, starting with a letter. Unique per Workspace; the URL segment of a Project and the prefix of its future ticket ids.
- **Column** — one step of a Project's workflow. Belongs to one Column category, has a name and a colour, and is ordered by a fractional-index position. Every Project keeps at least one `unstarted` and one `done` Column.
- **Column category** — what a Column means: `backlog`, `unstarted`, `started`, `done` or `canceled`. Fixed; Projects choose the names, not the categories.
- **Task** — a unit of work in a Project, sitting in one Column. Its state is the Column's category; there is no separate status. Has a title, a markdown description, a Priority, an optional Assignee, start date, due date and repeat rule, and a ticket id.
- **Start date / due date** — each is a day ("Friday") or a moment ("Friday 15:00"). A day is stored as 00:00 UTC and read the same by everyone; a moment is an instant shown in the reader's Time zone. A start date after the due date is refused; a due date moved before the start clears it (`docs/adr/0012-task-dates-and-recurrence.md`).
- **Time zone** — a user's IANA zone, or none to follow the browser. Decides "today", overdue, quick picks, how times read and the zone a new Recurrence is written in. Private to the user.
- **Recurrence** — an RFC 5545 rule (`DTSTART` plus one `RRULE`) on a Task whose `DTSTART` is its due date. Morrow accepts `FREQ`, `INTERVAL`, `BYDAY`, `BYMONTHDAY`, `BYMONTH`, `UNTIL` and `COUNT`. Only the newest open Occurrence carries the rule; cancelling, archiving or deleting it, or clearing the rule or the due date, ends the series.
- **Occurrence** — one Task of a repeating series. Moving a Task with a Recurrence into a `done` Column creates the next Occurrence in the same transaction (first `unstarted` Column, at the top, next due date, subtasks recreated open) and moves the rule to it. Comments, attachments and Relations stay on the old one.
- **Ticket id** — the Project key and the Task's per-Project number, as in `MOR-12`. Numbers are never reused; renaming the key renames every ticket id. A Task that moves to another Project gets a new Ticket id there; its old one keeps resolving to it.
- **Assignee** — the one Member a Task is assigned to, if any. Taking a Task for yourself needs only `task: update`; assigning anyone else needs `task: assign`. Leaving the Workspace clears assignments.
- **Priority** — `none`, `low`, `medium`, `high` or `urgent`.
- **Completed task** — a Task in a `done` or `canceled` Column, stamped with when it got there (`completedAt`); leaving the Column clears it.
- **Archived task** — a Task taken off the board and list but kept in its Column and position, so unarchiving puts it back. Still editable.
- **Label** — a name and a colour that belongs to a Workspace, ordered by a fractional-index position, and put on any number of its Tasks (at most 20 per Task). Renaming or recolouring it changes every Task at once; deleting it removes it from all of them. Names are unique per Workspace ignoring case.
- **Field** — a property a Project defines for its Tasks, with a name, a type fixed at creation and a fractional-index position (at most 20 per Project, names unique per Project ignoring case). Types: single choice, multi choice, text, number, date and checkbox; text and number carry a config (format, unit, bounds). A Task's values sit on the task row, keyed by Field id; a value not set is absent. Deleting a Field removes its values from every Task.
- **Option** — one choice of a single or multi choice Field, with an id, a name and a colour, ordered by position (at most 50 per Field). Tasks store the id, so renaming or recolouring changes every Task at once; deleting it clears it from all of them.
- **Comment** — a markdown message on a Task, up to 10,000 characters. Every Member may write one, Viewers included. Only its author edits it; its author or an Admin deletes it. Stays, as "Deleted user", when its author's account goes.
- **Subtask / Parent** — a Task can have one Parent Task in the same Project, to any depth. The Parent's row stores how many of its direct, unarchived Subtasks are closed (`done` or `canceled`) and how many there are. Nothing is enforced: a Parent can close with open Subtasks. Deleting a Parent keeps its Subtasks as top-level Tasks. A Subtask moves to another Project with its Parent; moved on its own it leaves the Parent.
- **Relation** — a link between two Tasks of a Workspace, in the same Project or not: `blocks` (the other Task reads "blocked by"), `related` (one link per pair) or `duplicate` (the other reads "duplicated by"). Nothing is enforced. Loops of `blocks` are refused. Deleting either Task removes it.
- **Task history** — the record of user-made changes to a Task: created, title, Column move, Priority, Assignee, start and due dates, repeat rules and Occurrences (`recurred`, on both Tasks), labels, archive and description edits, a Parent being set, changed or cleared (on the Subtask, and on each Parent involved), and Relations added or removed (on both Tasks). Repeated edits by one person within 10 minutes fold into one entry; an edit undone within that window leaves none. Changes the system makes (a Column deleted, a label deleted, a member removed) are not recorded.
- **Document** — a page of rich text in a Workspace, at its root or in one Project, edited by several people and agents at once (`docs/adr/0014-documents-on-yjs-and-durable-streams.md`). Its content is a Yjs document on Durable Streams, mirrored into Postgres as ProseMirror JSON, markdown and text. Has a title and icon of its own, outside the content. Members create and edit; Admins delete.
- **Page tree** — Documents nest under Documents, to any depth, ordered by a fractional-index position. There is no folder type: a Document with children shows as a folder. A Document and everything under it share one Project, and move, archive and restore together. Deleting a Document moves its children up one level.
- **Checkpoint** — a saved copy of a Document's content, taken before an agent run, on the first MCP write in a 10-minute window, every 10 minutes of changed content and before a restore. Restoring one applies it as a new change; it is how an agent's edit is undone.
- **Page job** — `document-settle`, the debounced job per Document in the `worker` process that repairs block ids and invalid structure, enforces the 1 MB limit, mirrors the body and takes interval Checkpoints.
- **Author names** — who wrote each piece of a Document's text, read from the Yjs client id on each item and the user it is registered to.
- **Admin** — a user whose verified session email is in `ADMIN_EMAILS`. Not stored in the database. Admins are exempt from the workspace limit and reach other workspaces through the administration pages, not the workspace URL.
- **Registration** — sign-up by email OTP, Google or GitHub. Closed by `REGISTRATION_OPEN=false`.
- **Vertical** — a folder named by what its code does, with the same name in API and web (`workspace`, `members`, …). It has one public `index.ts`; other verticals import only that.
- **Procedure** — an oRPC endpoint. Context comes from the Better Auth session: base, authenticated, workspace (permission-checked), admin.
- **Shape** — a server-defined, read-only stream of one table's rows for one user, served at `/api/shapes/:name`. The server fixes the table, columns and filter; the browser only names the shape.
- **Synced collection** — a TanStack DB collection fed by a Shape, living in the browser tab. Reads are live; writes go through Procedures. Cleared at sign-out.
- **Device preference** — a setting that belongs to the browser, not the user (theme, compact mode, sidebar default). Stored locally, synced between tabs, kept after sign-out.
